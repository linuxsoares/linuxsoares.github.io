Tratando o Claude Code como Colega de Time: Desenvolvendo com o Multica

Rodar o Claude Code em um terminal funciona muito bem para uma tarefa por vez. Você abre uma sessão, descreve o que quer, acompanha o trabalho e revisa o diff. Mas, quando começa a equilibrar várias tarefas — uma correção de bug aqui, um refactor ali, uma pequena feature esperando no backlog —, o terminal deixa de ser o lugar certo para gerenciar esse trabalho. Você acaba com uma pilha de abas, sessões pela metade e nenhuma visão clara do que cada agente está fazendo.

É esse o problema que o Multica resolve. Ele é um workspace source-available e self-hostable em que agentes de código trabalham como colegas de time: você atribui uma issue, eles pegam a tarefa, informam o progresso, sinalizam bloqueios e devolvem o trabalho para revisão. Ele não traz um modelo próprio — usa as CLIs de agentes que você já tem instaladas, e o Claude Code é uma delas.

Veja como configurar e usar no dia a dia com o Claude Code.

Como o Multica se organiza

Antes de instalar qualquer coisa, vale conhecer as peças:

  • Workspaces — agentes, issues e configurações separados por time ou projeto.
  • Issues — unidades de trabalho. Você atribui uma issue a um agente do mesmo jeito que atribuiria a uma pessoa.
  • Agents — colegas de time com nome, cada um com um provedor (como o Claude Code) e um runtime.
  • Runtimes — as máquinas onde os agentes realmente rodam. Cada uma roda um pequeno daemon, então seu código fica na sua máquina.
  • Skills — playbooks reutilizáveis que os agentes compartilham, para que uma boa forma de fazer algo só precise ser escrita uma vez.
  • Squads — agentes e pessoas em um mesmo time, com um líder distribuindo o trabalho.
  • Autopilots — tarefas agendadas para coisas como standups, auditorias e relatórios.

A ideia central: o servidor do Multica é o quadro, e o daemon no seu notebook é o trabalhador que roda o claude quando uma issue chega até ele.

Passo 1: instale a CLI

No macOS ou no Linux, o Homebrew é o caminho mais fácil:

brew install multica-ai/tap/multica

Garanta que o próprio Claude Code esteja instalado e com login feito — o Multica usa o binário claude que você já tem, ele não traz o dele:

claude --version

Passo 2: conecte e inicie o daemon

Se você usa o Multica Cloud, um único comando configura a CLI, faz a autenticação no navegador e inicia o daemon:

multica setup

Prefere manter tudo na sua própria infraestrutura? O Multica pode ser self-hosted com Docker. O script de instalação pode trazer o servidor junto, e o setup self-host aponta a CLI para ele:

curl -fsSL https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.sh | bash -s -- --with-server
multica setup self-host

Depois, confirme que o daemon está rodando e que encontrou o Claude Code:

multica daemon status

O daemon detecta automaticamente as CLIs de agentes no seu PATH, então o claude deve aparecer na lista de agentes detectados. Se ele estiver em um lugar incomum, aponte o daemon para ele:

export MULTICA_CLAUDE_PATH="$HOME/.local/bin/claude"

Passo 3: crie um agente Claude

No app web, abra Agents → New agent, escolha sua máquina como runtime e o Claude Code como provedor, e dê um nome a ele. É por esse nome que você vai atribuir trabalho. Dá para conferir pelo terminal:

multica agent list

O ciclo do dia a dia: entram issues, saem revisões

É aqui que o Multica muda o fluxo de trabalho. Em vez de abrir uma sessão no terminal, você escreve uma issue:

multica issue create --title "Add pagination to the /posts endpoint" --assignee "claude"

Ou atribui uma que já existe:

multica issue assign <issue-id> --to "claude"

A partir daí, o daemon pega a tarefa e roda o Claude Code no seu repositório. Dois detalhes importam muito aqui:

  1. Cada tarefa roda isolada. O Multica mantém um clone em cache do repositório e dá a cada tarefa seu próprio git worktree em ~/multica_workspaces. Dois agentes trabalhando em duas issues nunca mexem nos arquivos um do outro.
  2. O trabalho vai para revisão, não para a main. Quando o Claude termina, a issue vai para revisão. Você lê o diff como leria o pull request de um colega.

Enquanto ele trabalha, você acompanha sem se conectar a nenhum terminal:

multica issue runs <issue-id> --active   # what is running right now
multica issue run-messages <task-id>     # the full message log for a run
multica issue usage <issue-id>           # how many tokens it took

O log de execução registra cada tool call e cada comando que o agente rodou, o que torna revisar como ele chegou a um resultado tão fácil quanto revisar o próprio resultado. Se o agente travar, ele sinaliza um bloqueio na issue, e você responde com um comentário — no app web ou com multica issue comment add.

Dicas para ter bons resultados com o Claude

Mantenha um CLAUDE.md no seu repositório. O Claude Code lê esse arquivo em toda execução, então ele é o melhor lugar para descrever suas convenções: como rodar os testes, como os commits devem ser, o que não deve ser mexido. Como toda tarefa do Multica começa de um worktree novo, é esse arquivo que dá o mesmo contexto a cada execução.

Escreva issues como escreveria para uma pessoa. Um título claro, o comportamento esperado e como verificar. Um agente que sabe conferir o próprio trabalho entrega revisões muito melhores.

Ajuste o daemon com variáveis de ambiente. Algumas que acho úteis:

export MULTICA_CLAUDE_MODEL="opus"               # model used by Claude Code tasks
export MULTICA_DAEMON_MAX_CONCURRENT_TASKS=3     # default is 20 — keep your laptop breathing
export MULTICA_AGENT_IDLE_WATCHDOG=30m           # stop runs that go quiet (default 2h)

Deixe o daemon iniciar sozinho. Assim você nunca esquece de colocar seus agentes online:

multica daemon autostart enable

Transforme instruções repetidas em Skills. Se você vive escrevendo as mesmas orientações nas issues (“sempre adicione um teste”, “atualize o changelog”), isso merece virar uma skill que todos os agentes podem reutilizar.

O veredito

O Claude Code já é um desenvolvedor capaz. O que o Multica adiciona é o time em volta dele: um quadro em que o trabalho fica visível, worktrees isolados para as tarefas rodarem em paralelo com segurança, uma etapa de revisão antes de qualquer coisa chegar à main e um log de tudo o que o agente fez.

A mudança de mentalidade é o verdadeiro ganho. Parei de pensar “vou abrir o Claude e fazer isso” e passei a pensar “vou escrever uma boa issue e atribuir”. Se você já usa o Claude Code todos os dias e sente o peso de gerenciar várias sessões ao mesmo tempo, experimente o Multica.
